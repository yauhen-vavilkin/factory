### 4. Researcher Agent Design Discussion

**Goal:** Agent that investigates a Jira ticket before coding starts, using iterative tool calls.

**Key gap in current architecture:**
- `AbstractLlmAgentWorker` is single-shot (`callForText` / `callForEntity`).
- Researcher needs an **agentic tool loop** — Spring AI supports this via `ChatClient` + `ToolCallingManager`, but the base class does not expose it.

**Proposed approach:**
- New base class or extension for tool-calling workers.
- Single `AGENT` step in a new `researcher` flow.
- Minimum tool set for v1: Jira (read issue/comments/linked), GitHub (read file/search), local workspace (read_file with path validation, ripgrep with hit limit).
- Second phase: Confluence connector, JDT LS.

## 1. Зачем Jira-креды (email + API token)? Раньше работало без ключа — просто ссылка на тикет и ключ проекта. Это сильное усложнение конфигурации.

**Статус: обсуждено (2026-10-24).**

Проверенные факты (живые пробы + код ветки):

| Jira endpoint | Анонимно | Для чего |
|---|---|---|
| `GET /rest/api/2/issue/{key}` | 200 OK | прочитать один известный тикет |
| `POST /rest/api/2/search/jql` | 200 OK | финальный поиск задач в discovery |
| `GET /rest/agile/1.0/board/{id}/filter` | **401** (проверено) | board → сохранённый фильтр → JQL скоуп |
| `GET /rest/agile/1.0/sprint/{id}` | **401** (agile API) | определить спринт в скоупе |

- `JiraProperties.isReadable()` = только baseUrl; анонимный режим чтения в коннекторе есть
  (записи запрещены). Креды нужны не «просто так».
- Старый Developer Flow (origin/main) читал только один тикет по ссылке — это работает
  анонимно. Пилот же сам находит задачи: board/saved-filter + **sprint** + статусы. Шаги
  board и sprint идут через agile API Atlassian, который не отдаётся анонимно даже на
  открытом сайте — ограничение платформы Atlassian, не наш архитектурный выбор.
- Решение «обязательный sprint в скоупе» зафиксировано в плане (Global Constraints:
  «one explicit sprint», «Sprint and eligible statuses are required») — то есть это
  утверждённое решение, а не самовольное.
- Фрикшн-находка: `.env.pilot.example` требует email/token, но `scripts/start-pilot.sh`
  их **не проверяет** — без кредов стек стартует, а discovery падает позже малопонятным 401.

Вывод: требование кредов — внешнее ограничение Atlassian (agile API), вызванное сменой
источника задач (автономный discovery вместо ссылки на тикет). Само требование — из
утверждённого плана.

Открытые вопросы:
1. Принять email+token как цену автономного discovery — или пересматривать скоуп
   (спринт сейчас обязателен, saved-filter без спринта всё равно требует agile API).
2. Добавить fail-fast проверку Jira-кредов в старт скрипта (readiness check) вместо
   позднего 401.
